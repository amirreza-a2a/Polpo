# 12: RFC 8089 Compliant file:/// URI Formatting for Windows Cross-Platform Safety

**What to build:** Guarantee that canonical Markdown output URIs conform to RFC 8089 (`file:///...` with three slashes) across Linux, macOS, and Windows using `Path.as_uri()`. This prevents silent path corruption and drive-letter truncation (`C:\...` parsed as netloc and stripped) on Windows machines, while preserving backward compatibility for legacy two-slash URIs already persisted in the database.

**Blocked by:** None (independent of Ticket 11, can start immediately).

**Status:** ready-for-agent

## Scope & Boundary

- In `application/services/document_publication_service.py` (lines ~149, 298, 404), replace manual `f"file://{final_file.resolve().as_posix()}"` strings with `final_file.resolve().as_uri()`.
- In `application/services/legacy_document_backfill.py` (lines ~47-50), update `resolve_canonical_file_path()` to handle standard RFC 8089 URIs (`file:///C:/...` and `file:///path`) safely.
- **Implementation Note (Backward Compatibility):** The old code `f"file://{path.as_posix()}"` never produced malformed URIs on POSIX systems because POSIX absolute paths already start with `/` (resulting in `file:///path`, three slashes). The backward-compatibility risk is strictly Windows-specific: the legacy code produced `file://C:/artifacts/output_1_v1.md` (only two slashes before the drive letter), causing Python's `urlparse()` to treat `C:` as `netloc`, which downstream `url2pathname(unquote(parsed.path))` then dropped. Fixing `resolve_canonical_file_path()` for this case requires detecting a drive-letter-shaped `netloc` (a single ASCII letter followed by `:`) and re-prepending it to the path, rather than relying on `urlparse()`'s default netloc/path split.

## Non-Goals

- Migrating existing database rows to rewrite legacy two-slash strings into three-slash URIs (handled via backward-compatible resolution in `resolve_canonical_file_path()`).
- Changing non-canonical artifact URI formats managed by legacy subsystems.

## Acceptance Criteria

- [ ] All published document versions in `document_versions.output_path` and `jobs.output_path` store standard RFC 8089 URIs generated via `Path.as_uri()` (three slashes: `file:///...`).
- [ ] `resolve_canonical_file_path()` correctly round-trips URIs with Windows drive letters without dropping the drive letter or misinterpreting it as netloc.
- [ ] Backward compatibility: `resolve_canonical_file_path()` correctly resolves legacy Windows-style two-slash `file://` URIs (e.g. `file://C:/artifacts/output_1_v1.md` and `file://D:/...`) that may already exist in `document_versions.output_path` or `jobs.output_path` from before this fix.
- [ ] Zero manual `f"file://{...}"` string interpolations remain in `DocumentPublicationService` or `legacy_document_backfill.py`.
